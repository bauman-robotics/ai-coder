# Инструменты Tool Loop

Документация по инструментам, которые доступны агенту `ai_coder` в режиме
**tool loop**. Каждая итерация цикла — это один вызов инструмента,
результат которого возвращается модели для следующего шага.

Всего поддерживается **5 инструментов**:

| Инструмент   | Назначение                              | Опасный |
|--------------|-----------------------------------------|---------|
| `read_file`  | Чтение содержимого файла                | нет     |
| `list_files` | Просмотр структуры каталога             | нет     |
| `write_file` | Создание / перезапись файла             | да      |
| `edit_file`  | Точечная правка уникальной подстроки    | да      |
| `run_shell`  | Запуск whitelisted-команды              | да*     |

\* `run_shell` опасен тем, что выполняет внешние процессы, но ограничен
whitelist-ом, таймаутом и лимитом вывода.

---

## 1. `read_file`

Читает содержимое файла по относительному POSIX-пути.

### Аргументы

| Имя    | Тип    | Обяз. | Описание                                  |
|--------|--------|-------|-------------------------------------------|
| `path` | string | да    | Относительный путь к файлу (POSIX).       |

### Пример вызова

```json
{"tool": "read_file", "args": {"path": "ai_coder/tools.py"}}
```

### Что возвращает

Содержимое файла как текст, **до 50 000 символов**. Если файл больше —
результат обрезается, и модель должна работать с началом файла либо
запросить конкретные участки через `run_shell grep`.

### Опасный?

**Нет.** Только чтение, диск не изменяется.

---

## 2. `list_files`

Возвращает список файлов в каталоге. Используется для разведки структуры
проекта перед правками.

### Аргументы

| Имя       | Тип    | Обяз. | Описание                                            |
|-----------|--------|-------|-----------------------------------------------------|
| `dir`     | string | нет   | Относительный каталог, по умолчанию `.`             |
| `pattern` | string | нет   | fnmatch-шаблон, например `*.py` или `test_*.py`     |

### Пример вызова

```json
{"tool": "list_files", "args": {"dir": "tests", "pattern": "test_*.py"}}
```

### Что возвращает

По одному файлу на строку. Каталоги заканчиваются символом `/`.

```
tests/
tests/conftest.py
tests/test_tools.py
```

### Опасный?

**Нет.** Только чтение метаданных каталога.

---

## 3. `write_file`

Создаёт новый файл или полностью перезаписывает существующий.

### Аргументы

| Имя       | Тип    | Обяз. | Описание                          |
|-----------|--------|-------|-----------------------------------|
| `path`    | string | да    | Относительный путь к файлу        |
| `content` | string | да    | Полное новое содержимое файла     |

### Пример вызова

```json
{
  "tool": "write_file",
  "args": {
    "path": "docs/state.md",
    "content": "# Состояние\n\nОбновлено.\n"
  }
}
```

### Что возвращает

Сообщение-подтверждение, например `WROTE docs/state.md`.

### Опасный?

**Да.** Полная перезапись уничтожает прежнее содержимое. Перед использованием
проверяй, что файл можно перезаписывать целиком. Для точечных изменений
используй `edit_file`.

---

## 4. `edit_file`

Заменяет **уникальную** подстроку `old` на `new` внутри файла.

### Аргументы

| Имя    | Тип    | Обяз. | Описание                                       |
|--------|--------|-------|------------------------------------------------|
| `path` | string | да    | Относительный путь к файлу                     |
| `old`  | string | да    | Подстрока для поиска (должна быть уникальной)  |
| `new`  | string | да    | Замена                                         |

### Пример вызова

```json
{
  "tool": "edit_file",
  "args": {
    "path": "tests/test_cli.py",
    "old": "def test_help():",
    "new": "def test_help_alias():"
  }
}
```

### Что возвращает

Подтверждение, например `EDITED tests/test_cli.py`, либо ошибку
`'old' found N times`, если подстрока встречается больше одного раза,
или `'old' not found`, если её нет.

### Опасный?

**Да.** Изменяет существующий файл. Требует уникальности `old`.

---

## 5. `run_shell`

Запускает одну whitelisted-команду без метасимволов.

### Аргументы

| Имя           | Тип    | Обяз. | Описание                                        |
|---------------|--------|-------|-------------------------------------------------|
| `command`     | string | да    | Одна команда, например `pytest -q`              |
| `timeout_sec` | int    | нет   | Таймаут в секундах, по умолчанию 30, максимум 120 |

### Пример вызова

```json
{"tool": "run_shell", "args": {"command": "pytest -q", "timeout_sec": 60}}
```

### Что возвращает

`stdout + stderr` (до 10 000 символов). Если код возврата ≠ 0,
поле `ok=False`, но вывод всё равно доступен модели.

### Опасный?

**Да, но ограничен.** Разрешены только команды из whitelist:
`pytest`, `ruff`, `mypy`, `git status/diff/log`, `ls`, `cat`, `grep`, `find`.
Запрещены метасимволы `;`, `&`, `|`, `<`, `>`, `$`. Сеть и установка
пакетов недоступны.

---

## Безопасность

Tool loop спроектирован так, чтобы минимизировать риск необратимых правок.

### Whitelist

`run_shell` принимает только заранее одобренные команды. Список задаётся
в `ai_coder/tools.py` и проверяется перед запуском. Всё прочее — отклоняется
с ошибкой `whitelist_violation`.

### Dry-run

Флаг `--dry-run` заставляет `write_file`, `edit_file` и `run_shell` не
производить реальных действий. Вместо этого возвращается сообщение вида
`(dry-run) EDITED ...`. Удобно для оценки плана модели без риска.

### Interactive

Флаг `--interactive` приостанавливает цикл перед каждым опасным
инструментом и ожидает подтверждения оператора (y/n).

### Бэкап

Перед первым изменением файла создаётся резервная копия в
`tool-loop-ts/backups/`. При откате можно восстановить исходное состояние.

### Лимиты

| Лимит                    | Значение            |
|--------------------------|---------------------|
| Вывод `read_file`        | 50 000 символов      |
| Вывод `run_shell`        | 10 000 символов      |
| Таймаут `run_shell`      | 30 с (макс. 120 с)   |
| Итераций tool loop       | задаётся `--max-iterations` |

---

## CLI-флаги

| Флаг                | Описание                                                        |
|---------------------|-----------------------------------------------------------------|
| `--tool-loop`       | Включает режим цикла инструментов вместо одного ответа LLM.     |
| `--max-iterations`  | Максимум итераций цикла (по умолчанию 20). Защита от зацикливания. |
| `--dry-run`         | Симуляция: инструменты не меняют диск и не запускают процессы.  |
| `--interactive`     | Подтверждение каждого опасного действия оператором.             |
| `--commit`          | Коммитит изменения после успешного завершения цикла.            |
| `--resume`          | Продолжает ранее прерванный tool loop из журнала.               |
| `--max-cost-rub`    | Ограничение стоимости прогона в рублях по прайсу моделей.       |

Пример запуска:

```bash
ai-coder --tool-loop --max-iterations 15 --interactive --max-cost-rub 100
```

---

## Журнал

Все шаги цикла пишутся в каталог `tool-loop-ts/`, названный по метке
времени запуска. Структура:

```
tool-loop-2026-10-08T16-24-05/
├── step-1.md            # шаг 1 — детали: инструмент, args, результат
├── step-2.md            # шаг 2 — детали
├── history.json         # машиночитаемая история: [{action, result}, ...]
└── report.md            # итог: успех, стоимость, бэкап, коммит
```

`history.json` используется `--resume` для продолжения.
Бэкап (при первом изменении) — в отдельной папке
`.ai-out/<project>/tool-loop-backup-<ts>/`.

## Примеры реальных задач

### 1. Поднять `cov-fail-under`

Цель: увеличить требуемое покрытие в `pyproject.toml` с 40 до 60.

1. `read_file(path="pyproject.toml")`
2. `edit_file(path="pyproject.toml", old="--cov-fail-under=40", new="--cov-fail-under=60")`

### 2. Исправить баг

Цель: в `ai_coder/usage.py` неверно суммируются токены.

1. `read_file(path="ai_coder/usage.py")`
2. `edit_file(path="ai_coder/usage.py", old="...", new="...")`
3. `run_shell(command="pytest tests/test_pricing.py -q")`

### 3. Проверить покрытие

Цель: убедиться, что тесты проходят порог.

1. `run_shell(command="pytest --cov=ai_coder --cov-fail-under=60 -q")`
2. Изучить вывод и при провале — вернуться к задаче 1.

### 4. Добавить тест

Цель: покрыть новую ветку в `ai_coder/tools.py`.

1. `read_file(path="ai_coder/tools.py")`
2. `read_file(path="tests/test_tools.py")`
3. `edit_file(path="tests/test_tools.py", old="...", new="...")`
4. `run_shell(command="pytest tests/test_tools.py -q")`

## Ограничения

- **Без `git push`.** Синхронизация с удалённым репозиторием запрещена.
- **Без сети.** Команды, требующие интернет, отклоняются.
- **Без `pip`.** Установка и удаление пакетов недоступны.
- **Таймаут 30 с** для `run_shell` по умолчанию (максимум 120 с).
- **Лимит вывода 10 000 символов** для `run_shell` (и 50 000 — для `read_file`).

## Troubleshooting

### `parse_error`

Модель вернула невалидный JSON. Проверь поле `reason` и лог `history.json`;
повтори итерацию с более явным форматом. Частая причина — переносы строк
внутри строкового аргумента.

### `whitelist` violation

`run_shell` получил команду вне списка. Разрешены только `pytest`, `ruff`,
`mypy`, `git status/diff/log`, `ls`, `cat`, `grep`, `find`. Убери метасимволы
и разбей команду на несколько вызовов.

### `'old' found N times`

`edit_file` нашёл подстроку более одного раза. Добавь 2–3 соседние строки
контекста в `old`, чтобы сделать её уникальной.

### `max_iterations`

Цикл достиг `--max-iterations` и остановился. Увеличь лимит или запусти
`--resume`, чтобы продолжить с места остановки.

### `dry-run`

В режиме `--dry-run` файлы не меняются, а команды не выполняются. Если
ожидалось реальное изменение — убери флаг. Результаты вида
`(dry-run) EDITED/WROTE/RAN` означают, что действие было симулировано.

## Как формулировать задачу агенту

По итогам реальных прогонов (задачи 10.x) — правила, которые
экономили время и деньги или спасали от зацикливания.

### 1. Промпт — короткий (< 15 строк)

Проблема: в задаче 10.8 промпт был 55 строк. Модель flash теряет
фокус — читает файл, забывает, что делать, читает другой.
Итог: 15 итераций, 0 правок, 1.82 RUB.

Правило: промпт < 15 строк. Если больше — разбить на несколько задач.

Плохо:

    Сделай итерацию 10.8: 6 файлов, 5 правок, 3 теста, [55 строк]

Хорошо:

    1. В ai_coder/config.py, класс AgentConfig, добавь 2 поля:
       tool_loop_history_max_chars: int = 10_000
       tool_loop_history_other_max_chars: int = 500

Отдельная задача на файл.

### 2. Без обратных кавычек в CLI-промпте

Проблема: если в промпте есть обратные кавычки, bash выполняет
содержимое как command substitution. Модель получает обрезанный
промпт.

Правило: не использовать обратные кавычки. Либо — через файл:

    cat > /tmp/task.txt << 'TASK'
    Замени в docs/tools.md строку old на new
    TASK
    python -m ai_coder.cli agent "$(cat /tmp/task.txt)" . --tool-loop

### 3. Один-два файла на задачу

Проблема: агент зацикливается, если задача касается 5+ файлов.

Правило: одна задача = 1 файл (иногда 2). Для 5+ файлов —
разбить или Python-скрипт.

### 4. --dry-run — только для предпросмотра

Проблема: в --dry-run edit_file не меняет файл. Модель видит
тот же контент → перечитывает → зацикливается.

Правило: --dry-run — только для 1-2 итераций. Для реальных
правок — без флага.

### 5. Сначала посмотреть — потом править

Что работает: задача «прочитай файл X, найди Y, скажи есть ли» —
1-2 итерации, успех. Модель сама решает: если Y есть — edit_file,
если нет — finish.

Плохо: «примени эти 5 правок» — модель не видит файл в первый момент.

Хорошо: «в файле X замени Y на Z, если Y есть. Если нет — finish
с summary».

### 6. Модель — flash для простого, v4-pro для сложного

- flash — быстрая, дешёвая, но игнорирует длинные правила
  при сложных задачах.
- v4-pro — дороже, но справляется с анализом.

Правило: если задача аналитическая или многошаговая —
используй --model deepseek-v4-pro.

### 7. Для 3+ точечных замен — Python/sed

Наблюдение: 3 edit_file через агента = 5-15 итераций, 0.1-1.8 RUB.
Через Python-скрипт — 30 секунд, 0 RUB.

Правило:

- Агент — для создания (написал docs/tools.md за 1 запуск),
  рефакторинга, сложных задач.
- Python/sed — для 1-3 точечных замен.

### Итог — чек-лист

Перед запуском агента:

- [ ] Промпт < 15 строк?
- [ ] Без обратных кавычек (или через файл)?
- [ ] 1-2 файла (не 5+)?
- [ ] Не --dry-run (если правки реальные)?
- [ ] Задача сформулирована как «найди + замени, если есть»?
- [ ] Модель соответствует сложности?
- [ ] Для 3+ замен — лучше Python?
