## 1. Критично (баги, дыры в безопасности)

### 1.1. Отсутствует CSRF/Origin-проверка на изменяющих endpoint’ах
**Суть:**
`POST /run`, `POST /stop/{run_id}`, `POST /diff` изменяют состояние системы (запуск subprocess, убийство процесса, чтение git-дифа) и не проверяют `Origin`, `Referer` или CSRF-токен. GUI слушает только `127.0.0.1`, но браузер может отправить cross-origin POST из вредоносного сайта.

**Зачем:**
Защита от запуска агента с произвольными параметрами, остановки процессов и чтения diff’ов через посещение злобной страницы. Сейчас доступен полный функционал агента, включая `--apply`, без явного согласия пользователя.

**Как:**
Добавить проверку `Origin`/`Referer` для state-changing роутов либо внедрить CSRF-токен в форму. Минимально — middleware с проверкой `Sec-Fetch-Site: same-origin` и/или `Origin` из разрешённого списка.

**Трудозатраты:** **M**

---

### 1.2. Статическая раздача `.ai-out` отдаёт секреты и внутренние данные
**Суть:**
`app.mount("/ai-out", StaticFiles(...))` раздаёт весь каталог `.ai-out`, включая `usage.jsonl`, raw-ответы LLM, журналы с промптами и артефактами. В комментарии прямо сказано, что там могут быть секреты.

**Зачем:**
Даже при локальном бинде это лишний риск: утечка API-ключей/промптов через браузер, локальные процессы или случайный расшаривание скриншота/URL. Особенно опасно с учётом CSRF из п.1.

**Как:**
Убрать mount `StaticFiles` для `.ai-out`. Вместо этого сделать явный endpoint типа `GET /ai-out/{project}/{journal}/report.md` с:
- валидацией `Project` и `Journal` через `_safe_report_path`,
- отдачей только `report.md`,
- `Content-Type: text/markdown`,
- `X-Content-Type-Options: nosniff`.

**Трудозатраты:** **M**

---

### 1.3. Неуправляемый жизненный цикл subprocess в `/run`
**Суть:**
`/run` создаёт `subprocess.Popen` с блокирующим stdout-чтением через `StreamingResponse`. Если клиент отключается, сервер может остаться с hung-процессом. Остановка по кнопке шлёт `SIGTERM`, но:
- нет тайм-аута на завершение,
- нет kill процесса, если SIGTERM не сработал,
- нет очистки `RUNNING` при серверном shutdown.

**Зачем:**
Предотвращение утечек процессов и зависших агентов, накопления `RUNNING`, блокировок портов и неадекватных расходов на API.

**Как:**
Заменить на `asyncio.create_subprocess_exec` с асинхронным чтением, явным `terminate()` → `kill()` по таймауту, регистрацией cleanup на shutdown. В MVP можно оставить sync, но добавить `proc.terminate()` → `proc.kill()` в обработчик `/stop` и в `finally` `_stream_process` с ограничением `proc.wait(timeout=5)`.

**Трудозатраты:** **M/L**

---

### 1.4. Ошибки в построении команды для пути с пробелами
**Суть:**
В `_build_command` для `agent`-ветки путь подставляется без экранирования:
```python
parts.append(path_val)  # не _escape_shell(...)
```
Для `chain`-ветки тоже. При `path = "my project"` команда разваливается на два аргумента при `shlex.split`.

**Зачем:**
Пути с пробелами — обычное явление, GUI должен генерировать корректную команду. Косвенно это ещё и источник путаницы в отображаемой команде.

**Как:**
Не собирать строку и парсить её обратно. Строить список `argv` напрямую из полей формы, экранирование не нужно. Если строка обязательна для отображения — генерировать её отдельно из того же `argv`.

**Трудозатраты:** **S/M**

---

### 1.5. `advanced_flags` передаётся без валидации
**Суть:**
`advanced_flags` приходит от пользователя и добавляется в команду как есть. Не OS-injection, но позволяет добавлять произвольные CLI-флаги (`--config`, `--max-iterations`, `--verify-commands` и т.д.), а также ломать отображение команды.

**Зачем:**
Ограничение поверхности управления и воспроизводимость команды из/в формы. Не должно быть неожиданных флагов, влияющих на безопасность агента.

**Как:**
Определить whitelist допустимых advanced-флагов или хотя бы валидировать через `shlex.split` и предупреждать о непонятных опциях. В идеале — структурировать форму.

**Трудозатраты:** **S**

## 2. Архитектура и структура

### 2.1. Разделить монолитный `ai_coder/gui/app.py`
**Суть:**
Файл содержит и роуты, и командостроение, и сбор журналов, и статистику, и работу с документацией. Сейчас это ~600+ строк, при дальнейшем росте станет необслуживаемым.

**Зачем:**
Изоляция ответственности, упрощение тестирования, ревью и расширения GUI.

**Как:**
Вынести в пакет `ai_coder/gui/services/`:
- `command_builder.py` — сборка argv,
- `process_manager.py` — запуск/остановка subprocess,
- `journal_service.py` — сбор журналов, метаданные, безопасный доступ,
- `docs_service.py` — чтение docs/cli и рендеринг,
- `stats_service.py` — статистика.

Все роуты оставить в `app.py`.

**Трудозатраты:** **M**

---

### 2.2. Убрать дублирование конфигурации Ruff
**Суть:**
В проекте одновременно есть `ruff.toml` и `[tool.ruff]` в `pyproject.toml`. Настройки почти одинаковые, но уже есть расхождения: в `pyproject.toml` игнорируется `RUF059`, в `ruff.toml` — нет.

**Зачем:**
Избежать неоднозначности, какую конфигурацию реально применяет Ruff, и потенциальных багов в CI.

**Как:**
Оставить один источник — `ruff.toml` или `[tool.ruff]`. Выбрать и удалить второй, выровнять содержимое.

**Трудозатраты:** **S**

---

### 2.3. Убрать дублирование зависимостей между `pyproject.toml` и `requirements.txt`
**Суть:**
`pyproject.toml` содержит полный список runtime-зависимостей, `requirements.txt` — почти тот же список. При обновлении легко забыть синхронизировать.

**Зачем:**
Единый источник правды для установки и сборки. Меньше дрейфа версий.

**Как:**
Использовать `pyproject.toml` как основной, а `requirements.txt` убрать или генерировать через `pip freeze` при сборке. README оставить рекомендацию `pip install -e .`.

**Трудозатраты:** **S**

---

### 2.4. Вынести глобальные пути в конфигурацию
**Суть:**
`AI_OUT_DIR = Path.cwd() / ".ai-out"` и `DOCS_CLI_DIR = Path.cwd() / "docs" / "cli"` вычисляются в момент импорта. При запуске из другого каталога пути могут вести не туда.

**Зачем:**
Надёжность запуска GUI независимо от CWD, возможность переопределения для тестов.

**Как:**
Использовать Pydantic Settings / переменные окружения с дефолтами относительно корня проекта. Передавать через внедрение зависимостей.

**Трудозатраты:** **S**

## 3. Читаемость и поддерживаемость

### 3.1. Объединить сигнатуры `/build` и `/run` в одной модели
**Суть:**
`POST /build` и `POST /run` дублируют ~16 одинаковых `Form(...)` параметров. При добавлении нового поля легко забыть обновить оба роута.

**Зачем:**
Меньше дублирования, единый контракт формы.

**Как:**
Завести датакласс или Pydantic-модель `BuildRequest`, использовать FastAPI `Depends` для парсинга формы. Оба роута получают одну и ту же модель.

**Трудозатраты:** **S**

---

### 3.2. Упростить `_build_command` / `_build_argv`
**Суть:**
Сейчас команда сначала собирается как строка, затем парсится `shlex.split` в `_build_argv`. Это два источника правды и источник проблем с кавычками/пробелами.

**Зачем:**
Улучшить читаемость, устранить класс багов с экранированием.

**Как:**
Разделить представление для GUI (строка) и выполнение (`argv`). Строить `argv` первично, а строку рендерить из него. `_build_argv` не должен вызывать `_build_command`.

**Трудозатраты:** **S**

---

### 3.3. Усилить типизацию и docstrings в `gui/app.py`
**Суть:**
Часть функций/методов без docstring, есть cast, некоторые типы излишне общие (`dict`, `object`).

**Зачем:**
Повышение надёжности mypy и читаемости.

**Как:**
Добавить `->` и docstrings ко всем route handler, заменить `dict[str, object]` на TypedDict/dataclass, прогнать mypy с более строгими флагами.

**Трудозатраты:** **S**

## 4. Тесты

### 4.1. Покрыть `POST /run` и `POST /stop/{run_id}`
**Суть:**
Сейчас smoke-тесты покрывают все роуты, кроме `/run` и `/stop`, потому что они запускают subprocess.

**Зачем:**
Это ключевые endpoint GUI, их регрессии самые дорогие.

**Как:**
Мокать `subprocess.Popen` / `RUNNING`, тестировать:
- запуск процесса с корректным argv,
- стриминг вывода,
- остановку по SIGTERM,
- очистку `RUNNING` после завершения.

**Трудозатраты:** **M**

---

### 4.2. Добавить тесты на path traversal и symlink-атаки
**Суть:**
Сейчас есть `_safe_report_path`, `_safe_docs_cli_path`, проверка symlink в `_collect_journals`, но явных тестов на них в предоставленном коде не видно.

**Зачем:**
Подтвердить надёжность защиты от `..`, URL-encoded `%2F`, symlink-выхода.

**Как:**
Добавить тесты:
- `/reports/..%2F..%2Fetc/passwd` → 404,
- symlink на внешний каталог в `.ai-out` → не индексируется,
- `/docs/cli/..%2F..%2FREADME` → 404.

**Трудозатраты:** **S**

---

### 4.3. Тесты на командостроение с пробелами, кавычками и `advanced_flags`
**Суть:**
`_build_command` / `_build_argv` не покрыты краевыми случаями: путь с пробелами, goal с кавычками, `advanced_flags` с инъекцией.

**Зачем:**
Профилактика багов п.1.4/1.5.

**Как:**
Написать юнит-тесты с проверкой итогового `argv`. Ожидаемый результат — список аргументов без разбиения по пробелам, если они внутри пути/goal.

**Трудозатраты:** **S**

---

### 4.4. Добавить тесты для `_stream_process` и утечек процессов
**Суть:**
Логика обработки завершённого процесса, отключения клиента и таймаута не протестирована.

**Зачем:**
Предотвратить regression в управлении процессами и утечки после изменения кода.

**Как:**
Мокать `Popen`, генератор, имитировать клиентский disconnect, проверять вызовы `terminate`/`kill` и очистку `RUNNING`.

**Трудозатраты:** **M**

## 5. Производительность

### 5.1. Кэшировать рендер документации `/docs/cli/*`
**Суть:**
`_render_docs_cli_md` вызывает `markdown.markdown` на каждый запрос. Страницы документации статичны.

**Зачем:**
Меньше CPU-нагрузки и задержки при повторных обращениях.

**Как:**
Добавить `functools.lru_cache` на функцию рендера с ключом `(path, mtime)`. При изменении файла кэш инвалидировать.

**Трудозатраты:** **S**

---

### 5.2. Оптимизировать сбор журналов
**Суть:**
`_collect_journals` читает каждый `report.md` дважды: для метаданных и для первой строки. Можно читать один раз.

**Зачем:**
Ускорение `/reports` при большом количестве журналов.

**Как:**
Прочитать файл целиком один раз, извлечь метаданные и заголовок из одного объекта. Дополнительно ограничить глубину сканирования / использовать `os.scandir`.

**Трудозатраты:** **S**

---

### 5.3. Добавить пагинацию `/reports`
**Суть:**
`/reports` сейчас отдаёт список всех журналов. При большом числе прогонов это лишняя нагрузка и UX-проблема.

**Зачем:**
Масштабируемость при накоплении журналов.

**Как:**
Кэшировать общий список и рендерить страницы по 20–50 записей с query-параметром `page`.

**Трудозатраты:** **M**
