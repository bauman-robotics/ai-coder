# UI: идеи и план

Документ описывает **варианты графического интерфейса** для `ai-coder`
и **порядок** их реализации. Связан с `docs/roadmap.md` → Направление 8.

**Дата создания:** 2026-10-13
**Статус:** идеи (не начато).

---

## 1. Зачем UI

**Сейчас — консоль.** Хорошо для скриптов и экспертов. Плохо для:

1. **Постановка задачи** — длинный `goal` в терминале, кавычки, backticks.
2. **Просмотр отчётов** — `.ai-out/<project>/*.md`: найти, открыть, прочитать.
3. **История** — `usage.jsonl`, `chain-<ts>/`, `agent-<ts>/` разбросаны.
4. **Выбор инструментов** — надо помнить флаги.
5. **План** — `y/n/e` в терминале, нельзя посмотреть diff удобно.
6. **Прогресс** — если задача 5 минут, сидишь и ждёшь.
7. **Стоимость** — текст, не графики.

    pip install -e ".[gui]"
    uvicorn ai_coder.gui.app:app --reload --port 8000
    # http://127.0.0.1:8000/

**Сделано (A.11–A.13):**

- **A.11** — `run`-команды в GUI: `greet`, `inventory`,
  `suggest_improvements`, `explain` (форма работает с `agent`
  и `run`). ✅
- **A.12** — расширения формы:
  - **«Вставить команду»** — `<details>` с textarea + кнопка
    «Заполнить форму» → `parseCommand` → `applyParsed`. ✅
  - **Загрузка goal из файла** — `<input type="file">` + FileReader
    → `#goal`. ✅
  - **Поле `--issue <path>`** — `#issue` + `parseCommand` +
    `_build_command`/`_build_argv`/`build`/`run`. ✅
  Сделано: Task 1+2 — агентом (`--tool-loop --issue`), Task 3 —

  блокируются, если несовместимы. ✅

**Не умеет (A.14+):**

- Встроенный терминал (PTY + WebSocket, этап B).
- Пагинация / фильтр по проекту в `/reports`.
- Экспорт статистики в CSV / PNG / SVG.

См. `next-chat/in-progress.md` → A.14.

- Встроенный терминал (PTY + WebSocket, этап B) — **интерактив**
  (`--interactive`, `y/n/e`) **не работает**.
- Пагинация / фильтр по проекту в `/reports` (при 83 строках
  не нужно; при 500+ — добавить).
- Экспорт статистики в CSV / PNG / SVG.
- Графики (Chart.js): стоимость по дням, моделям, проектам.
- Сохранение **настроек** формы в localStorage (только path).
- Кнопка **«Скопировать с этой точки»** (только полный вывод).
- **Безопасность `/ai-out`:** сейчас — вся папка (может содержать
  `usage.jsonl`, raw-ответы); для публичного Web — фильтр `*.md`.

**Отличие от исходного плана** (§ 2–4 этого документа):

- **Было:** `--interactive-agent` wizard на `typer.prompt` (4 ч).
- **Стало:** веб-панель FastAPI + HTMX (уже A.0–A.4).
- **Причина:** встроенный терминал (этап B) требует WebSocket —
  FastAPI даёт его **из коробки**; Pydantic v2 уже в проекте;
  открывается в браузере.

## 2. Что рекомендую — приоритеты

**Сначала — не UI, а «улучшения UX» (дешёво, полезно):**

### 2.1. `--interactive-agent` — wizard (~4 часа)

Интерактивная форма **сверху** CLI. Без нового интерфейса — только
`typer.prompt`.

    $ ai-coder
    Задача: _
    Файлы (опционально): _
    Режим: [tool-loop / decompose / plan / chain]
    Бюджет (RUB): _
    → подтверждение → выполнение

**Плюсы:** 4 часа, решает 80% боли (goal в терминале).
**Минусы:** не UI, но UX.

### 2.2. `ai-coder report` — список задач (~4 часа)

Удобная команда — **не** UI.

    ai-coder report                  # список задач
    ai-coder report --last           # последняя
    ai-coder report --failed         # только провалы

**Плюсы:** быстро, полезно.
**Минусы:** всё ещё консоль.

### 2.3. `ai-coder run "..."` без sub-command (~1 день)

Автовыбор режима: `ai-coder "..."` → tool-loop по умолчанию.

**Плюсы:** меньше флагов.
**Минусы:** может угадать неверно.

### 2.4. Watch-mode (~4 часа)

    ai-coder agent "..." --watch

Прогресс **печатается** в реальном времени. `Ctrl+C` — стоп.

**Плюсы:** не «сидишь и ждёшь».
**Минусы:** только прогресс, не интерактив.

**Итого:** 1.5–2 дня. **Ощутимо** лучше.

## 3. Настоящий UI — три варианта

### 3.1. HTML-отчёты (A) — ★☆☆ сложность, 1–2 дня

**Что:** `ai-coder report --format html` → статический HTML:

- список задач из `.ai-out/`;
- стоимость, diff, журналы;
- графики (Chart.js);
- **просмотр** в браузере.

**Плюсы:**

- **Быстро** — Jinja2 + CSS, без backend.
- **Дёшево** — 1–2 дня.
- **Полезно сразу** — читать отчёты и историю.
- **Не требует** запуска сервера.

**Минусы:**

- **Только чтение** — задачу не поставишь.
- **Генерировать** каждый раз (`ai-coder report --format html`).
- **Ограниченный** интерактив.

**Идея:** просмотр — уже большое облегчение. Дополняет CLI, не заменяет.

### 3.2. TUI (Textual) (B) — ★★☆ сложность, 3–5 дней

**Что:** `ai-coder tui` — интерактив в терминале:

- список задач слева;
- лог агента справа;
- форма постановки задачи;
- план — `y/n/e` через кнопки, с diff;
- графики стоимости.

**Плюсы:**

- Работает **везде**, где есть терминал — SSH, VPS, Linux-сервер.
- **Естественное** продолжение `rich` (уже используется).
- **Полный** интерактив: задача → план → выполнение → отчёт.
- **Быстрее** HTML: не надо генерировать.

**Минусы:**

- **TUI** — не GUI: мышью не кликнешь, drag-and-drop нет.
- **Textual** — новая зависимость.
- **Сложнее** HTML: reactive-модель.

**Идея:** для разработчиков — **идеально**. Ты и так в терминале.

### 3.3. Web GUI (FastAPI + HTMX) (C) — ★★★ сложность, 1–2 недели

**Что:** `ai-coder web` — браузерный интерфейс:

- форма постановки задачи (textarea, чекбоксы);
- прогресс агента (WebSocket, стриминг логов);
- план — визуальный diff, редактирование;
- история — список задач, фильтры;
- графики — стоимость по дням, моделям, проектам;
- настройки — конфиг через UI.

**Плюсы:**

- **Настоящий** GUI — мышь, drag-and-drop, широкий экран.
- **Прогресс** виден в реальном времени.
- **История** — таблицы, фильтры, красиво.
- **Поделиться** с коллегами — открыть URL.

**Минусы:**

- Требует запуска **сервера**.
- **1–2 недели** работы.
- **Рефакторинг** `cli.py` в сервисный слой (`ai_coder.core.*`
  без Rich/Typer).
- **Деплой** — где-то хостить.

**Идея:** настоящий продукт. Но дорого и не срочно.

## 4. Порядок реализации

**Рекомендуемый:**

1. **UX-улучшения** (wizard, report, watch) — 1.5–2 дня.
2. **HTML-отчёты** (A) — 1–2 дня.
3. **TUI** (B) — 3–5 дней.
4. **Web GUI** (C) — **только если**:
   - несколько пользователей;
   - нужно делиться (открыть коллеге);
   - есть 1–2 недели.

**Почему так:**

- Wizard — **самое больное** (goal в терминале). 4 часа = 80% боли.
- HTML — **дёшево**, сразу польза.
- TUI — **то же**, что Web, но **дешевле** и **правильнее** для одного разработчика.
- Web — **дорого**, **не факт**, что нужен.

## 5. Предпосылки (для Web)

**Рефакторинг `cli.py` в сервисный слой:**

- `ai_coder/core/*` — бизнес-логика **без** Rich/Typer.
- `ai_coder/cli/*` — обёртка с Typer.
- `ai_coder/web/*` — FastAPI (если нужно).

**Плюсы** рефакторинга:

- Тестируемость (не надо мокать Rich).
- Переиспользование (CLI + TUI + Web).

**Минусы:**

- 1–2 дня.
- Много изменений.

**Связь:** ревью v4-pro → 2.4 «Рефакторинг `cli.py` в сервис».
