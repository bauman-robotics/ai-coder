> цены — обновить «Стоимость». См. `docs/state.md` → «Как обновлять».

Простое объяснение: **что умеет** `ai-coder` **сейчас**, **что появится**
в будущем, и **зачем** это нужно.

Для тех, кто **не** погружён в код проекта. Технические детали — в
`README.md`, `docs/state.md`, `docs/roadmap.md`.

---

## Что это

`ai-coder` — **помощник для программиста**. Работает в терминале.
Даёшь ему **задачу человеческим языком** — он **сам** разбирается
в проекте, **сам** делает правки, **сам** проверяет результат.

**Пример:**

    ai-coder agent "В файле calc.py функция add возвращает неверный результат. Исправь баг так, чтобы тесты проходили." ~/projects/myapp --tool-loop --apply

Через минуту-две:

    ✅ успех
    Итераций: 2
    Стоимость: 0.09 RUB
    Summary: Исправлен баг в calc.py: функция add теперь возвращает a + b

**Ты не открывал редактор. Не запускал тесты. Не искал баг.**
Всё сделал `ai-coder`.

---

## Кому полезен

**Программисту-одиночке:**

- рутинные правки: «добавь docstring в этот файл», «обнови README»;
- разбор чужого кода: «объясни, что делает эта функция»;
- массовые правки: «добавь тесты для всех функций в `utils.py`».

**Команде:**

- ревью проекта: «найди уязвимости и потенциальные баги»;
- работа с issues: «выполни задачу из issues/123.md»;
- пакетные задачи: «сделай все issues по очереди».

**Не для:**

- архитектурных решений (LLM не заменяет опытного инженера);
- задач «в голове у заказчика» (нужна чёткая формулировка);
- C/C++/JS пока (только Python, см. «Что в плане»).

## Что умеет сейчас

### 1. Анализ проекта (без правок)

    ai-coder run greet .                    # обзор проекта
    ai-coder run inventory .                # список классов/функций
    ai-coder run suggest_improvements .     # предложения по улучшению
    ai-coder run explain . --only-path x.py # объяснить файл

**Стоимость:** 0.05–0.15 RUB. **Ничего не меняет** — только отчёт.

### 2. Правки кода

    ai-coder run add_docstrings . --apply   # добавить докстринги
    ai-coder run write_readme . --apply     # сгенерировать README
    ai-coder run refactor . --apply         # рефакторинг

**Бэкап** перед каждой правкой. **Verify** (`py_compile`, `pytest`) после.
**Откат** при провале — `ai-coder rollback <backup>`.

### 3. Агент (LLM сам вызывает инструменты)

    ai-coder agent "добавь в calc.py функцию sub(a, b) = a - b" . --tool-loop --apply

Агент **сам**:

- читает файл (`read_file`);
- правит (`edit_file`);
- запускает тесты (`run_shell`);
- завершает (`finish`).

**Ограничения:** бюджет (`--max-cost-rub`), итерации (`--max-iterations`).

### 4. Разбиение на подзадачи

    ai-coder agent "обнови README, добавь тесты, исправь баг в x.py" . --decompose --tool-loop --apply

v4-pro **разбивает** задачу на 2–5 подзадач. Каждая — отдельный tool loop.
**При провале** — `replan` (skip/modify/stop).

### 5. Работа с задачами из файлов

    ai-coder agent --issue issues/123.md . --tool-loop --apply

**Задача — в Markdown-файле.** Удобно для:

- GitHub issues (`gh issue view 123 > issues/123.md`);
- своих задач (`issues/*.md`);
- roadmap-кусков.

### 6. Планирование перед выполнением

    ai-coder agent "большая задача человеческим языком" . --plan

Агент **показывает план**, спрашивает `y/n/e`:

- `y` — выполнить;
- `n` — отмена;
- `e` — править план в `$EDITOR`.

**Экономия:** планирование **не повторяется** при `y`.

### 7. Пакетная обработка issues

    ai-coder agent . --chain issues/ --tool-loop --plan

Все `issues/*.md` — **по очереди**. Один `y/n/e` на все. Итоговая таблица:
сколько сделано, сколько упало, стоимость.

### 8. Разбиение фразы на issues

    ai-coder agent "добавь sub, mul, div + README + тесты" . --split-goals

v4-pro **разбивает** фразу на N issue-файлов. **Не выполняет** — только
создаёт файлы. Потом — `--chain`.

**Полная цепочка:** `--split-goals` → правишь issues → `--chain --plan` → выполнить.

### 9. Авто-исправление ошибок

    ai-coder fix . --verify "pytest -q" --max-attempts 3

Цикл: `verify → fix → verify`. При провале — **сам** пытается починить.

### 10. Учёт расходов

    ai-coder usage              # сводка
    ai-coder usage --by-action  # по действиям
    ai-coder usage --by-day     # по дням

Все запросы пишутся в `usage.jsonl`. **Пиковые/непиковые** тарифы,
кэш, курсы CNY/RUB/USD.

### 11. Reverse-check — вторая проверка

    ai-coder agent "почини баг" . --tool-loop --apply --reverse-check

После **успеха** — LLM **перечитывает свой diff** и проверяет:
соответствует ли он задаче? Ловит ошибки, которые **тесты
не видят** (не тот API, порядок аргументов, недоделка связки).

**Стоимость:** ~0.04 RUB (маленький diff).
**Требует:** `--tool-loop`.
**Не работает:** `--decompose`, `--commit`, `--dry-run` (MVP).

## Что в плане

### Ближайшее

**1. `--interactive-plan`** — диалог уточнений.
Сейчас агент **угадывает** — «о каком файле речь?». Будет **спрашивать**.

**2. `--context-search`** — агент **сам ищет** контекст.
Сейчас — сужает по плану (иногда мимо). Будет — **разведка** перед планом.

**3. Память между запусками.**
Сейчас — **каждый запуск с нуля**. Будет — `.ai-out/<project>/tasks/`:
что делали, что узнали. `--resume-last` — «продолжаем».

**4. «Признание сложности».**
Сейчас — молча падает. Будет — «задача сложна для flash, попробуй v4-pro».

### Дальше

**5. Конвенции проекта.**
Агент **накапливает** знание: «тесты в `tests/`», «docstrings — Google-style».

**6. Reverse-check.**
LLM **перечитывает** свой diff: «соответствует ли goal?».

**7. Ветки + PR.**
Сейчас — коммит в текущую ветку. Будет — `ai-coder/<slug>-<ts>` + `gh pr create`.

**8. Рекурсивный replan.**
Если подзадача провалилась — **измельчить** и попробовать снова.

**9. Многоязычность (C/C++/JS).**
Сейчас — Python-only. Будет — язык по проекту.

**10. UI (HTML/TUI/Web).**
Просмотр отчётов, стоимость, diff.

## Как это работает (в двух словах)

1. **Сканирование.** `ai-coder` **обходит** проект (учитывает `.gitignore`).
2. **LLM.** Отправляет в **DeepSeek API** (flash или v4-pro) с промптом.
3. **Ответ.** LLM возвращает **JSON** — операции или вызов инструмента.
4. **Применение.** С **бэкапом**, **валидацией**, **verify**.
5. **Откат.** Если verify упал — **откатывает** правки, пробует fix.
6. **Учёт.** Каждый запрос — в `usage.jsonl`.

## Стоимость

**Flash** (дешёвая модель): ~0.05–0.3 RUB за задачу.
**v4-pro** (умная): ~0.5–3 RUB за задачу.

| Задача | Стоимость |
|---|---|
| `run greet` | 0.05 RUB |
| Простой bug fix (2 итерации) | 0.09 RUB |
| Разбиение фразы на 3 issues | 0.19 RUB |
| Chain из 3 задач с планом | 0.95 RUB |
| Decompose на 5+ файлов | 0.6–2 RUB |
| Ревью v4-pro (9 файлов) | 3.79 RUB |

**Бюджет.** `--max-cost-rub 2` — остановка при превышении.

---

## Безопасность

- **Blacklist.** `write_file`/`edit_file` **не пишут** в `.git/**`,
  `config/**`, `pyproject.toml`, `.env`.
- **Секреты.** `read_file`/`run_shell` **маскируют** API-ключи.
- **Shell.** Без `shell=True`. Whitelist команд.
- **Бэкап.** Перед **первой** правкой.
- **Флаги.** `--dry-run` — предпросмотр, `--interactive` — подтверждение.
