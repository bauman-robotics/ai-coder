# Доступ чата DeepSeek к консоли — варианты

**Вопрос:** можно ли дать веб-чату DeepSeek доступ к консоли,
чтобы он сам запускал `ai-coder`, читал вывод, правил файлы?

**Короткий ответ:** веб-чат DeepSeek — **изолирован**, не имеет
доступа к твоей машине. **Нельзя** дать ему консоль «в лоб».
**Можно** — через **локальные клиенты** (Open WebUI / Continue /
Cursor) или **MCP-сервер**. Разбор — ниже.

---

## Термины (для ориентира)

- **Function calling / tools** — стандарт в LLM API: модель не пишет
  текст, а возвращает **вызов инструмента** (`read_file`, `run_shell`).
  Клиент исполняет его на своей машине и возвращает результат в
  следующем запросе. **Мы это используем в `ai-coder` tool loop.**
- **MCP (Model Context Protocol)** — открытый стандарт (Anthropic),
  описывает, как LLM-клиенты подключают инструменты. Реализуется
  MCP-сервером, к которому подключаются Cursor / Claude Desktop /
  Continue.
- **Code Interpreter** — встроенная Python-песочница у некоторых
  чатов (ChatGPT, иногда DeepSeek). **Изолирована** в облаке —
  доступа к твоей машине нет.
- **Open WebUI** — self-hosted веб-чат с плагинами, работает с любым
  LLM API (включая DeepSeek), поддерживает tools.
- **Continue** — расширение для VS Code / JetBrains: чат + tool
  calling + доступ к файлам репозитория.
- **Cursor** — IDE с встроенной LLM и tools (файлы, терминал).

---

## Что предлагает DeepSeek

### A. Function calling в API — **есть**

DeepSeek API поддерживает tools. **Но** это работает **только через
API** (свой клиент). Веб-чат chat.deepseek.com — **не** даёт подключать
**свои** инструменты. Есть только встроенные (поиск, иногда code
interpreter).

**Вывод:** через веб-чат — нельзя. Через API-клиент (Open WebUI,
Continue, Cursor, свой код) — можно.

### B. Code Interpreter / артефакты — ограниченно

Если у твоей версии есть — модель запускает Python **в облаке
DeepSeek**, не на твоей машине. Доступа к `~/projects/15_ai_coder/` нет.

### C. MCP — напрямую нет, через клиентов — да

MCP **не** поддерживается веб-чатом. **Но** поддерживается:

- Cursor
- Claude Desktop
- Continue
- VS Code Copilot (частично)

Если поднять MCP-сервер на базе нашего `tools.py` — эти клиенты
смогут использовать наш tool loop.

---

## Три способа организовать сегодня

### Способ 1 — локальный чат с tools

**Варианты:**

- **Open WebUI** — self-hosted веб-чат, работает с DeepSeek API,
  поддерживает tools.
- **Continue** (VS Code / JetBrains) — чат в редакторе,
  tools, файлы репозитория.
- **Cursor** — IDE с LLM и tools.

**Плюс:** настоящий чат + доступ к машине.
**Минус:** поднимаешь сам, не веб-чат DeepSeek.

### Способ 2 — обёртка вокруг `ai-coder` + LLM

**Идея:** скрипт-репитер:

- ты пишешь в обычный чат DeepSeek;
- копируешь вопрос в скрипт;
- скрипт отправляет DeepSeek API запрос с доступом к `ai-coder`;
- вывод — в терминал;
- ты копируешь вывод обратно в чат.

**Это** — то, что мы делаем **вручную** сейчас. Можно автоматизировать,
но это уже CLI/TUI, не веб-чат.

### Способ 3 — MCP-сервер (через Cursor / Claude Desktop)

**Если** готов использовать Cursor или Claude Desktop:

- MCP-сервер даёт инструменты (`read_file`, `run_shell`, ...);
- модель (**в т.ч. DeepSeek в Cursor**) вызывает их сама;
- это **то же**, что наш tool loop, но в интерфейсе IDE.

---

## Можно ли прикрутить это к нашему `ai-coder`

**Идея:** сделать MCP-сервер из наших tools.

**Что уже есть:**

- 5 инструментов: `read_file`, `list_files`, `write_file`,
  `edit_file`, `run_shell`;
- безопасность: `_safe_path`, whitelist shell, таймауты;
- `run_tool_loop` — оркестратор.

**Что нужно:**

- JSON-RPC обёртка над `TOOL_REGISTRY`;
- запуск как MCP-сервер;
- конфиг для Cursor / Claude Desktop / Continue.

**Оценка:** ~2-3 дня.
**Ценность:** высокая — агент работает в IDE, без CLI, без
копирования вывода.

**Зависит:** от рефакторинга `cli.py` в сервис (ревью 2.4) —
чтобы MCP-сервер мог использовать ядро без Rich/Typer.

---

## Что реально работает сегодня

**Прямой ответ:**

- Веб-чат DeepSeek = только текстовый диалог, без доступа к твоей
  машине. Это **фундаментальное ограничение** платформы DeepSeek.
- **Можно:**
  - Open WebUI / Continue / Cursor — локальный клиент к DeepSeek API
    с поддержкой tools;
  - MCP-сервер на базе `tools.py` — стандарт, работает с Cursor /
    Claude Desktop;
  - или ручное копирование (как сейчас).

## Рекомендация

**Ближайшая цель** — не MCP, а направление 7 (UI) из `roadmap.md`.

**MCP** — логичное направление 8:

- 2-3 дня работы;
- зависит от рефакторинга `cli.py` в сервис;
- высокий приоритет после автономности.

**Когда делать:** после Сессий 1-5 (безопасность, автономность,
рефакторинг).

**Связанные термины и идеи для изучения:**

- Function calling / tools — спецификация в OpenAI API (у DeepSeek
  совместимая).
- MCP — спецификация на modelcontextprotocol.io.
- Open WebUI — github.com/open-webui/open-webui.
- Continue — continue.dev.
- Cursor — cursor.com.
