# Автономность: принципы и план

Документ описывает, **что такое автономность** в `ai-coder`, что
**уже работает**, что **мешает**, и **план** движения к полной
автономности. Связан с `docs/roadmap.md`, `docs/experiments.md`,
`TODO.md`.

**Дата создания:** 2026-10-10
**Статус:** активный план, Этап 1 (E8)

---

## 1. Что такое автономность

**Наивное определение:** «модель справляется с первого раза» — это
**качество модели**, а не автономность.

**Настоящее определение:** агент **сам** понимает провал, **сам**
перепланирует, **сам** доводит до результата. Модель может быть
**слабой** — автономность **компенсирует**.

**Четыре уровня:**

| Уровень | Что | Когда работает | Флаг |
|---|---|---|---|
| 1 | Одна попытка | Простые задачи | `--tool-loop` |
| 2 | Провалился → fix → успех | Verify упал | `--auto-fix-issues` |
| 3 | Декомпозиция + replan | Многошаговые задачи | `--decompose-replan` |
| 4 (цель) | Рекурсивный replan | Сложные задачи | *не реализовано* |

**Уровни 1-3 — есть.** **Уровень 4 — цель.**

## 2. Что уже работает

**Фундамент автономности:**

- **Tool loop** (9.1-9.4) — модель сама вызывает инструменты.
- **Retry при `missing args`** (10.14.26) — страховка от флейков.
- **`read_symbol`** (10.16) — точная навигация по Python.
- **`--auto-fix-issues`** (10.17) — цикл verify → fix → verify.
- **`--with-tests`** (10.19) — авто-тесты для изменённых файлов.
- **`--issue <file>`** (10.20) — задача из Markdown-файла.
- **Decompose + replan** (10.11.8) — v4-pro разбивает, replan
  при провале: skip/modify/stop.
- **Rollback при fail** (10.11.x) — откат успешных подзадач.

**Инфраструктура:**

- **Verify после `finish`** — pytest/ruff/mypy.
- **Бюджеты:** `--max-cost-rub`, `--decompose-max-cost-rub`.
- **Git-автокоммит** (`--commit`).
- **Безопасность** (10.15-10.18): blacklist, mask_secrets,
  `shell=False`, whitelist аргументов.

## 3. Что мешает

**Проблема 1 — планировщик разбивает «по смыслу», не «по исполнимости».**

**E7 (10.21):** задача 1.5 — `apply_plan` + `rollback`. v4-pro разбил
на 2 подзадачи, **первая = вся задача** (обе функции). Flash провалился
на `parse_error`.

**Что нужно:** планировщик должен понимать, что **две согласованные
функции в большом файле** — **сложно** для flash. Разбивать
**по функциям**, не по смыслу.

**Проблема 2 — replan получает мало контекста.**

**Сейчас:** `failed_error=loop_result.summary` (типа «max_iterations»).
**Что есть:** «не справилась».
**Что нужно:** «8 раз `read_file`, 2 `edit_file`, ошибки: `parse_error`,
`max_iterations`». **История подзадачи.**

**Проблема 3 — replan не умеет «измельчить».**

`modify` может дать **новую** подзадачу, но **такой же сложности**.
При повторном провале — **петля**.

**Проблема 4 — нет «признания сложности».**

Сейчас: `stop` после первого провала (если replan так решит). **Но**
если 3 раза подряд — **не** останавливается, **не** сообщает «задача
слишком сложная для flash».

## 4. Гипотезы

**H1.** **Граница flash:** ~7-10 строк goal, **1 функция**, **1 файл**.
Выше — растут флейки, `parse_error`.

**H2.** **2 согласованные функции** (например, `apply_plan` +
`rollback`) — **предел** flash. Требует **v4-pro** или **декомпозиции
по функциям**.

**H3.** **Replan с историей** (последние 5-10 шагов) — **точнее**,
чем по `summary`. Видит, **где** модель застряла.

**H4.** **Рекурсивный replan** (modify → fail → modify) — **спасает**,
если v4-pro умеет **измельчать**.

## 5. План

### Этап 1 — E8: граница flash (~20 мин)

**Что:** серия задач **нарастающей** сложности на песочнице.

**Задачи (6 штук):**
1. 1 функция, 1 правка, 3 строки goal. → mul(a, b).
2. 1 функция, 2 правки, 5 строк. → add + sub.
3. 2 функции, 2 правки, 7 строк. → mul + div с проверкой.
4. 1 функция в большом файле (500+ строк). → правка в apply.py.
5. 2 согласованные функции. → как в 1.5.
6. 3 функции, 3 правки. → набор math-функций.

**Замер:** итерации, `parse_error`, флейки, стоимость.

**Результат:** **точное правило** для `--issue` — «goal < N строк,
M функций».

**Артефакт:** `docs/experiments.md` → E8.

### Этап 2 — Улучшение replan (~2ч)

**A.** Передавать в replan **историю подзадачи** (последние 5-10 шагов):
- какие инструменты;
- ошибки;
- прогресс.

**B.** Промпт для v4-pro:
- «если `max_iterations` или много ошибок — **разбей мельче**»;
- «не повторяй формулировку, **измельчи**».

**C.** Тесты + smoke на **провале 1.5**.

**Артефакт:** CHANGELOG, тесты в `test_agent.py`.

### Этап 3 — E9: проверка на 1.5 (~15 мин)

**Что:** повторить задачу 1.5 с **улучшенным replan**.

**Замер:** справится ли flash с **более мелким** разбиением? Или
нужен v4-pro **на подзадачах**?

**Артефакт:** `docs/experiments.md` → E9.

### Этап 4 (опционально) — рекурсивный replan (~3ч)

**Что:** если `modify` даёт подзадачу, и она **снова** провалилась —
**дробить ещё раз**. Ограничение по **глубине** (2-3).

**Зачем:** Уровень 4 автономности.

**Артефакт:** CHANGELOG, тесты, E10.

---

### Этап 5 (после E9) — планировщик из human-goal

**Что:** пользователь даёт задачу **человеческим языком**,
агент **сам**:
1. Разбивает на подзадачи (v4-pro).
2. Показывает план.
3. Ждёт подтверждения.
4. Выполняет каждую подзадачу.
5. Адаптируется при фейле.

**MVP:** `--plan` — только разбиение, без выполнения
(~2-3 ч). **Уже есть** `run_planner_decompose` — нужно
добавить `--plan-only` и вывод.

**Полная версия:** `--interactive-plan` — диалог с агентом
(через `ask_user`, направление 6 в roadmap).

**Целевой уровень:** 4 (из 4) — «рекурсивный replan +
самоограничение + автоматическое разбиение».

**Основание:** E9 (2026-10-10) — агент работал в чужом
проекте, но пользователь разбивал вручную. Автоматизация
разбиения — следующий шаг.

**См.** `docs/roadmap.md` → направление 10.

## 6. Критерии успеха

**E8:**
- Точное правило для `--issue`: «goal < N строк, M функций».
- Warning в `--issue`, если превышено.

**Replan:**
- Передаёт историю (последние 5-10 шагов).
- Разбивает при `max_iterations` (промпт).
- Unit-тесты: 3+ (передача истории, измельчение, repeat-fail).

**E9:**
- 1.5 справляется через декомпозицию **без ручной работы**.
- Стоимость < 2 RUB.

**Документация:**
- `experiments.md` → E8, E9.
- `CHANGELOG.md` → итерация улучшения replan.
- `state.md` → обновление.
