# Roadmap — движение к автономности

План развития `ai-coder` в сторону **полной автономности агента**:
LLM сама вызывает инструменты, планирует, декомпозирует, чинит,
пишет тесты, создаёт PR.

**Основание:** полное ревью v4-pro от 2026-10-09
(`docs/reviews/v4-pro-2026-10-09-full.md`) + раздел
«Приоритизация для полной автономности» + гипотезы из
`docs/experiments.md`.

**Формат:** направление → что мешает → что делать → оценка → приоритет.

---

## Что **уже** работает (фундамент автономности)

- Tool loop: 5 инструментов, retry при `missing args` (10.14.26),
  правило 12 + правило 14.
- `read_file(line_start, line_end)` для больших файлов (10.14.14).
- Decompose + replan + rollback (10.11.x, 10.12).
- Verify после `finish(success)` (10.13).
- `--hint` — уточнение промпта (10.14.23).
- Бюджеты: `--max-cost-rub` для `fix`, `agent`, `decompose`.
- Git-автокоммит (`--commit`).
- Правила 1-14 в `agent_tool_json` + anti-loop эвристики.

---

## Что **мешает** полной автономности сегодня

1. **Одна задача за раз.** Нет очереди, нет chain.
2. **Нет памяти между запусками.** После `agent` — всё забывается.
3. **Агент не пишет тесты.** Verify проверяет, но новых тестов нет.
4. **Нет issue-driven** — работает только с CLI-промптом.
5. **Нет веток/PR** — только коммит в текущую ветку.
6. **Нет multi-turn** — не может спросить пользователя.
7. **5+ файлов** — либо decompose, либо фейл.

---

## Направления доработок

### 🟢 Направление 1 — `--auto-fix-issues`

**Что:** цикл `pytest → fix (tool loop) → pytest → ...`
до success или `--max-attempts`.

**Что уже есть:**
- `ai-coder fix` (10.14.1–10.14.3) — работает;
- `run_auto_fix` — цикл.

**Что нужно:**
- вызвать `run_auto_fix` из агента **после** правки;
- флаг `--auto-fix-issues` (opt-in).

**Оценка:** ~2 часа. **Риск:** низкий. **Приоритет:** 🟢 высокий.

**Ценность:** высокая — полный цикл «правка → verify → fix».

---

### 🟢 Направление 2 — `--with-tests`

**Что:** агент сам пишет тесты для изменённых файлов
(`test_<module>.py`, edge cases).

**Что нужно:**
- промпт `agent_tests_json`;
- после `finish(success)` правки — второй вызов «напиши тесты для
  изменённых файлов»;
- verify — `pytest` проходит.

**Оценка:** ~3 часа. **Риск:** средний (модель слаба на тестах).
**Приоритет:** 🟢 высокий.

**Ценность:** высокая — полноценная автономная доработка.

---

### 🟡 Направление 3 — `--issue <file>` (issue-driven)

**Что:** читает markdown issue (описание задачи) → план → выполнение.

**Что нужно:**
- парсинг issue-файла → goal для агента;
- флаг `--issue issues/123.md`.

**Оценка:** ~2 часа. **Риск:** низкий. **Приоритет:** 🟡 средний.

**Ценность:** средняя — удобно для GitHub-workflow.

---

### 🟢 Направление 4 — ветки + PR (Уровень D)

**Что:** перед работой — ветка `ai-coder/<slug>-<ts>`, push, PR через `gh`.

**Что нужно:**
- починить `slugify` для кириллицы (сейчас fallback `"task"`);
- создание ветки;
- `gh pr create` если есть `gh`;
- флаг `--branch`.

**Оценка:** ~4 часа. **Риск:** средний (push необратим).
**Приоритет:** 🟢 высокий.

**Ценность:** высокая — настоящий PR-workflow.

---

### 🟡 Направление 5 — multi-turn (`--interactive` чат)

**Что:** агент может задать вопрос пользователю — «какой файл править?».

**Что нужно:**
- инструмент `ask_user(question)`;
- в `--interactive` — панель и ввод;
- в headless — `stopped_reason="needs_input"`.

**Оценка:** ~4 часа. **Риск:** средний. **Приоритет:** 🟡 средний.

**Ценность:** средняя — для сложных задач, где модель не уверена.

---

### 🟢 Направление 6 — память между запусками

**Что:** состояние задачи сохраняется в
`.ai-out/<project>/tasks/<hash(goal)>/`:
- `goal`, `plan`, `attempts`, `costs`, `journal`;
- при повторном запуске с тем же `goal` — «продолжаем?» или
  автоматический resume.

**Что нужно:**
- хэш `goal` + проект;
- сохранение state после каждой итерации;
- `--resume-last` или автоматический вопрос.

**Оценка:** ~6 часов. **Риск:** высокий (много изменений).
**Приоритет:** 🟢 высокий (стратегическое).

**Ценность:** очень высокая — основа «агент-как-сервис».

## 🔴 Безопасность — до всего остального (из ревью 09-full)

Эти пункты **блокируют** автономность — без них агент может
сломать проект или утечь секреты.

### tools.py — blacklist (ревью 1.1)

- **Проблема:** tool loop обходит `apply_plan`-blacklist.
- **НО:** агент должен уметь улучшать себя — `config/` для `ai-coder`.
- **Фикс (вариант A):** `tool_loop.blacklist_enabled=true` по умолчанию,
  флаг `--allow-blacklist` для осознанного обхода.
- **Тесты:** default reject / с флагом allow.
- **Приоритет:** 🔴 высокий (с оговоркой). **Оценка:** S (~1 час).

### tools.py — content-фильтр секретов (ревью 1.2)

- **Проблема:** `_contains_secret` применяется только при скане,
  не в `tool_read_file`, `run_shell` (`cat`, `grep`).
- **Фикс:** в `tool_read_file` после чтения — `_contains_secret`;
  маскировать. Для `run_shell` — пост-фильтрация stdout.
- **Приоритет:** 🔴 высокий (утечка ключей). **Оценка:** S (~1 час).

### apply.py — `shell=True` в `run_verify_commands` (ревью 1.3)

- **Проблема:** `subprocess.run(cmd, shell=True)` — RCE-вектор.
- **Фикс:** `shlex.split(cmd)` + `shell=False` + whitelist.
- **Приоритет:** 🔴 высокий (RCE). **Оценка:** M (~2 часа).

### run_shell — whitelist аргументов (ревью 1.4)

- **Проблема:** `find . -delete`, `git branch -D` — опасные флаги.
- **Фикс:** чёрный список флагов для `find`, `git`.
- **Приоритет:** 🟡 средний. **Оценка:** M (~2 часа).

### apply.py — неатомарность (ревью 1.5)

- **Проблема:** пустые каталоги остаются при откате.
- **Фикс:** журнал созданных каталогов + удаление.
- **Приоритет:** 🟡 средний. **Оценка:** M (~2 часа).

## Архитектурные улучшения (не срочно)

### agent.py — разделение монолита (ревью 2.1)

- **Проблема:** `agent.py` — 2800 строк, всё в одном модуле.
- **Фикс:** `models.py`, `planner.py`, `tool_loop.py`, `autofix.py`.
- **Приоритет:** 🟡 средний. **Оценка:** L (~день).

### decompose — параллельные подзадачи (ревью 5.5)

- **Проблема:** подзадачи выполняются последовательно.
- **Фикс:** `ThreadPoolExecutor` для независимых.
- **Приоритет:** 🟢 низкий. **Оценка:** L (~день).

### agent.py — глобальный `_console` (ревью 2.3)

- **Проблема:** `_console = Console()` на уровне модуля — сложно тестировать.
- **Фикс:** инъекция через параметр/класс.
- **Приоритет:** 🟢 низкий. **Оценка:** S.

### run_agent_decompose (ревью 2.5)

- **Проблема:** функция делает всё — планировщик, подзадачи, retry,
  replan, отчёт.
- **Фикс:** выделить `_execute_subtask`, `_handle_replan`, `_save_report`.
- **Приоритет:** 🟡 средний. **Оценка:** M.
