# Roadmap — движение к автономности

План развития `ai-coder` в сторону **полной автономности агента**:
LLM сама вызывает инструменты, планирует, декомпозирует, чинит,
пишет тесты, создаёт PR.

**Основание:** полное ревью v4-pro от 2026-10-09
(`docs/reviews/v4-pro-2026-10-09-full.md`) + раздел
«Приоритизация для полной автономности» + гипотезы из
`docs/experiments.md`.

**Формат:** направление → что мешает → что делать → оценка → приоритет.

---

## Что **уже** работает (фундамент автономности)

- Tool loop: 5 инструментов, retry при `missing args` (10.14.26),
  правило 12 + правило 14.
- `read_file(line_start, line_end)` для больших файлов (10.14.14).
- Decompose + replan + rollback (10.11.x, 10.12).
- Verify после `finish(success)` (10.13).
- `--hint` — уточнение промпта (10.14.23).
- Бюджеты: `--max-cost-rub` для `fix`, `agent`, `decompose`.
- Git-автокоммит (`--commit`).
- Правила 1-14 в `agent_tool_json` + anti-loop эвристики.

---

## Что **мешает** полной автономности сегодня

1. **Одна задача за раз.** Нет очереди, нет chain.
2. **Нет памяти между запусками.** После `agent` — всё забывается.
3. **Агент не пишет тесты.** Verify проверяет, но новых тестов нет.
4. **Нет issue-driven** — работает только с CLI-промптом.
5. **Нет веток/PR** — только коммит в текущую ветку.
6. **Нет multi-turn** — не может спросить пользователя.
7. **5+ файлов** — либо decompose, либо фейл.
8. **Python-only** — C/C++/JS требуют доработок (направление 9).

## Направления доработок

### 🟢 Направление 1 — `--auto-fix-issues`

**Что:** цикл `pytest → fix (tool loop) → pytest → ...`
до success или `--max-attempts`.

**Что уже есть:**
- `ai-coder fix` (10.14.1–10.14.3) — работает;
- `run_auto_fix` — цикл.

**Что нужно:**
- вызвать `run_auto_fix` из агента **после** правки;
- флаг `--auto-fix-issues` (opt-in).

**Оценка:** ~2 часа. **Риск:** низкий. **Приоритет:** 🟢 высокий.

**Ценность:** высокая — полный цикл «правка → verify → fix».

### 🔴 Направление 2 — навигация (`read_symbol` + кэш)

**Что:** точная и быстрая навигация по проекту для tool loop —
без хранения структуры в БД.

**✅ A. `read_symbol(name)`** — новый инструмент tool loop — ЗАКРЫТО 2026-10-10
- ✅ Реализовано в 10.16 (`c66ec38` + `70e15d1`).
- Python-only (regex `^def`/`^class`/`^async def`);
  `path`/`kind` — опционально; декораторы, вложенные методы, коллизии.
- **Результат E2E:** 2 итерации вместо 3, 0.1125 RUB вместо 0.13.
- Побочный фикс: `format_tool_history` — `read_symbol` не обрезается.
- Для C/C++ — направление 9, уровень 1A.

**❌ B. Кэш сканирования (`scan-cache.json`)** — ОТКЛОНЕНО 2026-10-10
- **Что пробовали:** кэш содержимого файлов в `scan-cache.json`.
- **Замер:** `scan_project` = **0.014 s** (52 файла); полный `greet` =
  **12 s**. Скан — **0.1%** времени. Кэш 868 KB — замедлил, не ускорил.
- **См.** `docs/experiments.md` → E4 (отрицательный результат).
- **Правильная цель** (вместо кэша содержимого):

  **B.1. Кэш карты символов** (`symbols-cache.json`) — 🟡
  - `{path: {mtime, size, symbols: [{name, kind, start, end}]}}`.
  - Для `read_symbol` без `grep` — читаем структуру из кэша.
  - Размер ~50 KB (не 868 KB).
  - **Эффект:** `read_symbol` без regex-сканирования всех файлов.
  - **Оценка:** ~2 ч.

  **B.2. Инкрементальный контекст** — 🟢 (архитектура, не кэш)
  - Если изменились 3 файла из 50 — в промпт **только 3**.
  - **Эффект:** экономия **токенов** (главная статья расходов),
    не секунд. Токены → деньги.
  - **Оценка:** ~1 день. **Риск:** высокий (меняет логику скана).
  - См. `TODO.md` → «Инкрементальный контекст».

**Почему без БД:** 80% эффекта БД (навигация + переиспользование
структуры) — за ~6 часов, без схемы/миграций/парсера/watcher'а.

**Приоритет:** 🔴 высокий (после безопасности, до автономности).

**См. `docs/mcp-and-chat-integration.md`** — почему без БД.

- Список задач + боковая панель с логом агента.
- Работает везде, где есть терминал.
- Естественное продолжение `rich`, который уже используется.
- **Приоритет:** 🟡 средний. **Оценка:** M-L.

**C. Web GUI** (FastAPI + HTMX) — 1-2 недели

- **Приоритет:** 🟢 низкий (отложенное). **Оценка:** L.

рефакторинг) и **после** рефакторинга `cli.py` в сервис.

**Порядок:** A → B → C. Начать с **A** (HTML-отчёты) — быстро

**Предпосылка:** рефакторинг `cli.py` в сервисный слой

**Приоритет:** 🟡 средний (после автономности, до крупных фич).

### 🟡 Направление 9 — многоязычность (C/C++/JS/…)

**Что:** `ai-coder` сейчас заточен под Python. Сканер, промпты,
tool loop и verify — везде неявные предположения про `.py`. Для
работы с C/C++/JS/Go/Rust нужен слой абстракции «язык проекта».

**Зачем:** реальные проекты редко бывают mono-Python. C-вставки,
C++-ядро, JS-фронтенд, YAML-конфиги — обычная картина. Агент должен
уметь работать с ними, а не спотыкаться.

**Что уже работает на C (без доработок):**
- `run greet`, `run inventory`, `run explain`, `run write_readme` —
  промпты нейтральны, LLM понимает C;
- `edit_file` / `create_file` / `read_file` / `list_files` —
  языко-нейтральны;
- `run_verify_commands` — работает, если переопределить команды
  вручную (`--verify-commands "make"`).

**Что НЕ работает:**
- `run add_docstrings` — ищет `"""..."""`, C-комментариев не знает;
- `read_symbol` — Python-only (по дизайну);
- `run_shell` whitelist — нет `gcc`, `clang`, `make`, `cmake`;
- `check_python_files` — только `.py`, C не проверяет;
- промпт `agent_tool_json` — правила 1-14 под Python;
- нет автовыбора `verify_commands` по build-system.

**Что делать:**

**Уровень 1 — минимум (~1-2 дня):**
- **A.** `read_symbol` расширить: параметр `lang` (`python`|`c`|`auto`)
  или через `ctags` (universal-ctags, работает для всех языков).
  `~2-4 ч`.
- **B.** `run_shell` whitelist: `gcc`, `clang`, `make`, `cmake`,
  `ld`, `ar`, `nm`, `objdump`, `gdb`, `valgrind`. `~1 ч`.
- **C.** `verify_commands` — автовыбор: есть `Makefile` → `make`,
  `CMakeLists.txt` → `cmake --build`, `pyproject.toml` → `pytest`.
  `~2 ч`.
- **D.** `check_python_files` → `check_syntax_files`:
  для `.c`/`.h` — `gcc -fsyntax-only <file>`. `~2 ч`.

**Уровень 2 — средний (~3-5 дней):**
- **E.** Промпты для C: `add_docstrings_c` (`/** ... */`),
  `refactor_c`, `explain_c`. Или один промпт с `{{language}}`.
- **F.** Сканер: приоритизация под C — `Makefile`, `CMakeLists.txt`,
  `*.c`, `*.h` — высокий вес; `build/`, `*.o`, `*.a`, `*.so` —
  исключать. `~2 ч`.
- **G.** `read_symbol` через `ctags`: генерируем `tags` один раз,
  читаем по имени мгновенно. C, C++, Python, JS, Go — из коробки.
  `~4 ч`.

**Уровень 3 — большой (неделя+):**
- **H.** Секция `language` в `config.yaml`: разные промпты,
  whitelist'ы, verify_commands, приоритеты сканера — на язык.
- **I.** Build-system awareness: `Makefile`/`CMake`/`meson`/`bazel` —
  определение и использование правильных команд.
- **J.** Multi-language проекты (C-ядро + Python-обёртка):
  определение языка по файлу, а не по проекту.

**Приоритет:** 🟡 средний (после Сессии 1.5 — навигация; до UI).

**Ценность:** высокая — расширяет аудиторию с Python-only на
C/C++/JS/Go/Rust. Но **не блокирует** автономность на Python.

## 🔴 Безопасность — до всего остального (из ревью 09-full)

Эти пункты **блокируют** автономность — без них агент может
сломать проект или утечь секреты.

### tools.py — blacklist (ревью 1.1)

- **Проблема:** tool loop обходит `apply_plan`-blacklist.
- **НО:** агент должен уметь улучшать себя — `config/` для `ai-coder`.
- **Фикс (вариант A):** `tool_loop.blacklist_enabled=true` по умолчанию,
  флаг `--allow-blacklist` для осознанного обхода.
- **Тесты:** default reject / с флагом allow.
- **Приоритет:** 🔴 высокий (с оговоркой). **Оценка:** S (~1 час).

### tools.py — content-фильтр секретов (ревью 1.2)

- **Проблема:** `_contains_secret` применяется только при скане,
  не в `tool_read_file`, `run_shell` (`cat`, `grep`).
- **Фикс:** в `tool_read_file` после чтения — `_contains_secret`;
  маскировать. Для `run_shell` — пост-фильтрация stdout.
- **Приоритет:** 🔴 высокий (утечка ключей). **Оценка:** S (~1 час).

### apply.py — `shell=True` в `run_verify_commands` (ревью 1.3)

- **Проблема:** `subprocess.run(cmd, shell=True)` — RCE-вектор.
- **Фикс:** `shlex.split(cmd)` + `shell=False` + whitelist.
- **Приоритет:** 🔴 высокий (RCE). **Оценка:** M (~2 часа).

### run_shell — whitelist аргументов (ревью 1.4)

- **Проблема:** `find . -delete`, `git branch -D` — опасные флаги.
- **Фикс:** чёрный список флагов для `find`, `git`.
- **Приоритет:** 🟡 средний. **Оценка:** M (~2 часа).

### apply.py — неатомарность (ревью 1.5)

- **Проблема:** пустые каталоги остаются при откате.
- **Фикс:** журнал созданных каталогов + удаление.
- **Приоритет:** 🟡 средний. **Оценка:** M (~2 часа).

  - `issues/123.md` из GitHub;
  - свои задачи в `issues/*.md`;
  - позволяет «кормить» roadmap агенту **частями**.
- `--with-tests` (~3 ч) — **если** останутся силы.

### Сессия 4 (опционально) — автономность (**крупное**)

- ветки + PR;
- память между запусками.

### Сессия 5 (опционально) — новые фичи

- `--include <glob>`;
- `--style google|sphinx|numpy`.

## Как передавать задачи из roadmap агенту

**Нельзя** скормить roadmap целиком — промпт **305 строк**, а правило
из `docs/tools.md` — **< 15 строк**. Иначе флейки, зацикливание,
провал (см. эксперимент 10.8 и 10.14.25).

### Правильно: одна задача = один запуск

**Шаг 1.** Выбрать **одну** задачу из roadmap.

**Шаг 2.** Сформулировать **короткий** промпт (< 15 строк).

**Шаг 3.** Запустить:

    ai-coder agent "$(cat /tmp/task.txt)" . \
        --tool-loop --apply --max-iterations 20 --max-cost-rub 3

### Через `--issue <file>` (после реализации, направление 3)

**Формат задачи** — отдельный md-файл в `issues/`:

    # task: tools.py blacklist
    ## Цель
    Добавить проверку blacklist в write_file/edit_file.
    ## Файлы
    - ai_coder/tools.py
    - ai_coder/cli.py
    ## Тесты
    - test_tool_write_file_rejects_blacklist_default
    ## Ограничения
    Не менять apply.py.

**Запуск:**

    ai-coder agent "" . --tool-loop --apply --issue issues/1.1-tools-blacklist.md

**Плюс:** промпт **не** нужен — issue структурирован.
**Минус:** надо реализовать `--issue` (см. направление 3).

### Внешний orchestrator

**Скрипт** `run_roadmap.sh` — читает `roadmap.md`, парсит задачи,
запускает `agent` для каждой с коротким промптом.

    while read -r task; do
        ai-coder agent "$task" . --tool-loop --apply --max-cost-rub 2 \
            || { echo "STOP: $task failed"; exit 1; }
    done < <(grep '^### Задача ' roadmap.md | sed 's/^### Задача [0-9]*: //')

**Минус:** парсинг markdown нестабилен.

### Чек-лист перед запуском агента по roadmap

- [ ] Промпт < 15 строк?
- [ ] Без backticks (или через файл)?
- [ ] 1-2 файла (не 5+)?
- [ ] Не `--dry-run` (если правки реальные)?
- [ ] Задача — «найди + замени, если есть»?
- [ ] Модель соответствует сложности?
